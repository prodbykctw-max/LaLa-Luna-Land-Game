   undefined (reading 'setHex')`.** Verbatim from `qa/out/traversal.json` → `hub.pageErrors` (`traversal.mjs`'s
   ~1h hub run is the only suite long enough to trigger it — `console_load.mjs`'s ~60s hub run shows only the
   two pre-existing environmental entries, same as baseline). The only `setHex` call that fires every frame on
   hub is `index.html:5400`: `if(cfg.hub){ const all = G.letters.every(Boolean);
   I.castleLamps.forEach(l => l.material.color.setHex(all ? MOON : 0x8A7C60)); ... }`. `castleLamps` meshes are
   built once at hub construction (`index.html:4598-4604`) as plain `MeshBasicMaterial({color:MOON})`, which

   found 0 page errors of any kind) and the only suite that ran long enough to catch it — recommend a

## Fixes applied after this audit (same session, branch `qa-fixes-2026-09-12`)

No GitHub write access was attached to this session (`git push` was refused by the proxy: "not in this
session's authorized repository set"), so these are committed to a local branch and delivered as a patch file
(`qa-fixes-2026-09-12.patch`) rather than pushed/PR'd directly — same situation as the last report.

- **Hub `setHex` crash (Delta #1)**: added a guard at `index.html:5400` — `I.castleLamps.forEach` now checks
  `l && l.material && l.material.color` before calling `setHex`, and logs once (`DBG("castleLamp missing
  material/color", …)`) instead of throwing if it's ever missing. **Root cause not found this pass** — traced
  as far as: nothing else in `index.html` touches `I.castleLamps` after hub build, and the static-mesh batcher's
  `plainToon()` filter (`~3163`) excludes `MeshBasicMaterial` (what the lamps use), so it shouldn't be touching
  them either. A real repro needs another ~1h hub-only run (this is the only suite that's caught it in two
  audits now) with the new DBG line in place to see what it logs when it happens. Verified: inline script still
  parses (`new Function()` per `<script>` block) and a `console_load.mjs` run over hub/green/gr shows the same 2
  pre-existing environmental console entries as before the edit, no new errors introduced.
- **2 dead identifiers (Delta #12)**: removed `HEAD_EAR`, `HEAD_CROWN`, `HEAD_SIDE` (`index.html` ~1432-1457).
  Confirmed all three have zero references outside their own declarations; `HEAD_CROWN`/`HEAD_SIDE`'s comment
  claimed they were "kept so the physics clamp below still reads in the old names," but that clamp
  (`HAT_CLEAR`/`HAT_TILT_MAX`) already reads `HAT_RX`/`HAT_RZ`/`HAT_FIT` directly — the comment was stale.
  Removed the dead code and the comment describing a wiring that no longer existed.
- **"+2 lights per island" (Delta #3) — corrected, not a bug.** Traced to the new `TOON3D` lighting rig
  (`LOOK` defaults to `"toon3d"`, `index.html:481-482`; `TOON3D = LOOK !== "real"`): when true, per-island setup
  (`index.html:4018-4024`) adds a "bounce" and "rim" `DirectionalLight` on top of the existing hemisphere + key,
  by design ("A film rig, not a sun," per the code's own comment) — exactly +2, on every island, regardless of
  content, which is why the pattern was so uniform. No code change made; this line item in Delta #3 should be
  read as informational, not a regression.

**Not fixed this pass** (flagged, needs more than a quick edit):
- **Camera-in-geometry up on Hub/GR (Delta #2)**: the live per-frame camera clamp (`placeCamera`,
  `index.html:5045-5064`) already walks the arm against `I.height()` and `I.camBlobs` every frame during real
  play; whether `traversal.mjs`'s independent raycast sweep is exercising a gap in that clamp, or is measuring
  something the live clamp doesn't cover at all (e.g. a static per-frame check vs. the sweep's much larger
  sample set), wasn't determined this pass. Needs someone to compare what `traversal.mjs`'s camera-goal
  calculation assumes against the current `placeCamera`/`cameraCollide` implementation line-by-line — the two
  have likely drifted since the T1 fix given how much the file has grown around them.
- **`lala.glb` grown to 6.65 MB (Delta #4)**: this is binary mesh/texture data, not something to edit as text.
  The original A3 recommendation (Draco/meshopt compression + a decimation pass) still stands and needs
  asset-pipeline tooling (Blender or similar), not a code change.
